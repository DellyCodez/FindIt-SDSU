# CS 514 Phase 1 — submission checklist

Source: Professor Nguyen's **Final Database Product Project**, Phase 1 rubric (pp. 3–4) and team/AI expectations (pp. 1–3). This file is a working checklist, not proof of submission.

## Project rubric — 100 points

| Done | Item | Points | Owner / handoff |
| --- | --- | ---: | --- |
| [ ] | Draft presentation (8 minutes + 2 minutes Q&A; equal participation) | 25 | All; Samuel coordinates |
| [ ] | About page: hypothetical company, mission, members, roles, problem, value | 10 | Samuel drafts; all review |
| [ ] | Product overview + instructions | 10 | Samuel, with Alexander's verified demo |
| [ ] | Blog: **one original paragraph from each member** | 10 | Alexander, Andy, Samuel individually |
| [ ] | Source code and executable, GitHub link, original-contribution summary | 25 | Alexander + Andy; Samuel documents |
| [ ] | Technical PDF: design, implementation, course concepts, screenshots, user guide | 10 | Samuel assembles; Andy/Alexander supply evidence |
| [ ] | Confidential peer evaluations for teammates in **each person's Canvas submission comments** | 10 | Every member individually |
| | **Total** | **100** | |

The draft should be complete even if imperfect; aim for a working prototype. The submission website must be created with Google Sites, Wix, Weebly or another website builder and link to deliverables (except private peer evaluations).

## Separate peer-review discussion — 50 points

- [ ] Review at least two classmates' Phase 1 projects: functional/useful assessment, improvements, score out of ten, reasons (**30 points**).
- [ ] Reply substantively to at least two classmates' comments on our project, at least three quality sentences each (**20 points**).
- [ ] Post the team's draft website link to the Canvas discussion and submit the Phase 1 website URL in the assignment.
- [ ] Confirm exact due times and presentation sign-up in Canvas; do not assume the same deadline for each component.

## Before pressing submit

- [ ] App runs from documented steps on the demonstration machine.
- [ ] All links on the external project website open as intended.
- [ ] GitHub source points to the actual version shown in the demo.
- [ ] Technical PDF and presentation show real screenshots and tested statements only.
- [ ] Each member's contribution is genuine and identifiable in GitHub.
- [ ] AI assistance is truthfully identified, with the team's modifications and testing explained.
- [ ] No real student personal data or secrets are included.
- [ ] Presenter order and speaking time are rehearsed.
- [ ] A three-member team is approved by instructor/TA **or a fourth teammate is added**. The project instructions specify 4–6 students.
